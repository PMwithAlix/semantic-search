# معرفی محصول — Semantic Search Engine

این سند مکمل [README](../README.md) است و روی مسئله، مخاطب و ارزش محصول تمرکز دارد. جزئیات فنی در [ARCHITECTURE.md](./ARCHITECTURE.md) و وضعیت قابلیت‌ها در [FEATURES.md](./FEATURES.md) آمده است.

## مسئله

جست‌وجوی کلیدواژه‌ای وقتی کار می‌کند که Query و سند واژگان مشترک داشته باشند. در عمل، کاربران یک مفهوم را با جمله‌های متفاوت بیان می‌کنند: محاوره در برابر رسمی، مترادف، ترجمهٔ ناقص، یا توصیف علائم به‌جای نام فنی. نتیجه معمولاً «هیچ نتیجه‌ای پیدا نشد» یا رتبه‌بندی ضعیف است.

این پروژه همان شکاف را برای **جدول‌های CSV با schema دلخواه** هدف می‌گیرد: رکوردها به بردار معنایی تبدیل می‌شوند و Query نیز با همان مدل embed می‌شود تا نزدیک‌ترین ردیف‌ها با Cosine Similarity برگردانده شوند.

## آنچه محصول واقعاً هست

یک پلتفرم عملیاتی **CSV → Import → Embedding → Vector Collection → Semantic Search** با UI فارسی/انگلیسی و API جداگانه؛ نه یک موتور جست‌وجوی وب عمومی و نه یک RAG کامل با تولید پاسخ.

جریان محصولی تأییدشده از روی کد:

1. کاربر CSV آپلود می‌کند.
2. Worker ردیف‌ها را به‌صورت JSONB در PostgreSQL وارد می‌کند.
3. کاربر مدل Embedding (از کاتالوگ AvalAI) و ستون‌های متنی را انتخاب می‌کند.
4. Worker متن هر ردیف را از ستون‌های انتخاب‌شده می‌سازد، بردار می‌گیرد و در جدول pgvector همان Collection ذخیره می‌کند.
5. در جست‌وجو، Query embed می‌شود و نتایج با امتیاز Cosine (بازهٔ ۰ تا ۱) برمی‌گردند؛ فیلتر متادیتا و استنتاج محدود intent نیز اعمال می‌شود.

## کاربران هدف (بر اساس قابلیت واقعی)

| گروه | نیاز | ارزش فعلی محصول |
|------|------|------------------|
| توسعه‌دهنده | API و pipeline قابل تکرار برای جست‌وجوی معنایی روی دادهٔ جدولی | REST API، Swagger، Worker صف‌دار، Docker Compose |
| تحلیلگر داده | پیدا کردن ردیف‌های مشابه بدون ساختن query SQL پیچیده | UI جست‌وجو، فیلتر ستون‌ها، امتیاز شباهت و زمان اجرا |
| تیم تحقیق / NLP | مقایسه مدل‌های Embedding روی دادهٔ فارسی | کاتالوگ مدل، تخمین هزینه، اسکریپت‌ها و نتایج ارزیابی در `samples/` |
| کسب‌وکار دانش‌بنیان / پشتیبانی | بازیابی تیکت یا سند مشابه از CSV | دیتاست دموی تیکت پشتیبانی + pipeline عمومی برای هر CSV |
| تیم عملیاتی با دادهٔ مکانی | دیدن نتایج روی نقشه در صورت وجود مختصات | نمایش Leaflet وقتی ستون‌های مختصات معتبر باشند |

محدودیت محصولی مهم: استنتاج خودکار فیلتر از متن Query برای چند الگوی مخابراتی (مبدأ/مقصد کشور) نوشته شده است و یک لایهٔ NLP عمومی برای همهٔ دامنه‌ها نیست.

## ارزش پیشنهادی

- **جست‌وجو با معنا، نه فقط تطابق کلمه** روی دادهٔ ساخت‌یافتهٔ متنی.
- **Schema عمومی**: ستون‌های تیکت، محصول یا CDR hard-code نشده‌اند؛ متن Embedding از ستون‌های انتخاب‌شده ساخته می‌شود.
- **قابل نمایش به ذی‌نفعان**: UI کامل، progress جاب‌ها، Collectionهای جداگانه به‌ازای ترکیب مدل و ستون.
- **قابل استقرار محلی**: Docker برای API، Worker و PostgreSQL+pgvector.

آنچه محصول ادعا نمی‌کند: احراز هویت سازمانی، multi-tenant، RAG با LLM برای پاسخ نهایی، یا Vector DB جدا از PostgreSQL در نسخهٔ فعلی.
